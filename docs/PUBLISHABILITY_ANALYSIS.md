# 项目发文可行性严谨评估（2026-08-21）

> 目的：在 RetrySQL 实验进行期间，对项目的创新点、证据强度、短板与投稿层级做一次冷静评估。
> 数据基准：官方 test-suite 口径，Spider dev 1034 题。核心数字：多源池+ORM=86.1%；纯未见池=83.4%；MI-VAV=74.3/74.8；FINER 同口径复现=76.6%。

---

## 一、方法全景（三句话版本）

1. **多源候选池**：4 个同基座 checkpoint（蒸馏 SFT 三个演进版 + GRPO 旧模型）× 每题 16 采样 = 64 候选/题，保证 Pass@K。
2. **MI-VAV 执行分组**：对每题的所有官方 test-suite 数据库变体（25-60 个/题）执行候选 SQL，结果签名完全一致才归为一组——把"投票"建立在全实例执行等价上，天然对齐官方评测语义。
3. **ORM 训练型终裁**：3B 生成式 Yes/No 判卷老师（20,415 条自动打标轨迹训练，sigmoid(logit_Yes−logit_No) 校准），组级分 = 组人数 × P(Yes)，取最大。对 MI-VAV 提升 +9~11pp。

## 二、创新点分层（按可辩护强度排序）

### 强（可作为卖点）

**S1. ORM 的三级防污染检验方法学**（最硬）
- 同池考试 86.7% → 同门新题 82.4% → 异血统题 78.4%（vs 该池基线 67.7%）→ 纯未见池 83.4%。
- 意义：训练型判卷类方法（GradeSQL/JudgeSQL 一族）最大的陷阱是"背答案假象"，我们的三级检验是**可复用的验证协议**，不只是自家实验细节。评审人最爱这种自我质疑式的证据链。

**S2. 小模型阵营的竞争力证据**
- 纯 3B 小模型管线在 Spider dev 官方 test-suite 达到 86.1%——与用 GPT-4 级大模型的主流系统（榜单头部 86-88% 区间）同档，且判卷/推理成本低一个数量级。83.4% 的"纯未见池"数字是无可挑剔的头条（判卷老师对完全陌生血统仍 +9pp）。

**S3. 错误预算归因（天花板分析）**
- 池天花板 89.4% = 103 道生成侧错误 + 180 道选择侧错误。P1 三张牌全负（均衡重训 dev +3.9pp 官方不涨 / M8 采样负 / CAPS 级联负）共同证明：**瓶颈在候选池而非融合层**。这给"验证器路线"的论文提供了一个清醒的定位：验证器是必要的（+9~11pp）但不是充分的（天花板由生成侧决定）。

### 中（组合层面）

**M1. 多源多样性 × 训练型判卷的完整闭环**：多数论文只用单一模型的自洽采样；我们把"源多样性"与"学习型置信度"耦合，且每个源都带血统标记（可审计）。
**M2. 全实例执行分组的严格性**：分组语义与官方评测同构（任何变体结果不同即不同组），比 FINER 的单实例 VAV、R³ 的粗粒度分组更严格；附带跳过空组/全零组的语义处理。

### 弱（诚实标注，不能作为卖点）

- 三个组件单拎出来都有文献对应：多源采样（MARS-SQL/自洽家族）、执行分组（FINER/R³）、训练判卷（GradeSQL/JudgeSQL）。**新颖性在组合与验证方法学，不在单组件发明**。
- 未做理论分析；单尺度（3B）；Spider 单基准。

## 三、与文献的位置（2026 语境）

| 工作 | 规模 | 口径 | 数字 |
|---|---|---|---|
| FINER-SQL（ICDE'26） | 3B | BIRD dev 官方 | 67.8%；Spider 声称 85 |
| GradeSQL | 14B 级 | BIRD | ~64 |
| 我们 | 3B×4 源 | Spider dev 官方 | 86.1 / 83.4 |
| Spider 榜单头部（大模型） | GPT-4 级 | dev 官方 | ~86-88 |

关键点：我们的数字在小模型阵营有竞争力；但 **2024-2026 年 Text-to-SQL 的默认基准是 BIRD**，只有 Spider 会被评审直接质疑。

## 四、短板清单（评审人视角，按杀伤力排序）

1. **无 BIRD 评测**（致命伤候选）——同一管线在 BIRD dev 上跑一轮即可补，是当前性价比最高的一步。
2. **无 Spider test 集数字**——需要官方榜单提交或改用留出集；多数论文用 dev 也成立，但要说清楚。
3. **无逐源消融**——64 候选由 4 源组成，各源贡献、单源 vs 四源、16 vs 更多采样未拆开。补充后"多源"创新点才站得住。
4. **无基线对比表全貌**——需要 ≥3 个 2024-2026 同规模基线（FINER 复现 76.6 已有，缺 RetrySQL/ARES/GradeSQL 同口径数字）。
5. **89.4% 天花板的定义**是事后分析，需说明计算口径（哪些题判为生成侧不可达）。
6. 代码未整理发布（评审后 camera-ready 前需要）。

## 五、层级预测

- **CCF-B（EMNLP/COLING/NAACL/CIKM）**：**稳**。故事完整（小模型+验证器+多源+防污染方法学+负结果），数字有竞争力，写作材料（L7/L4 草稿）已齐。
- **CCF-A（ACL/ICDE/SIGMOD）**：**有条件够**。需同时满足：① BIRD 数字；② 逐源消融；③ 同规模基线对比；④ 训练侧（RetrySQL 在跑）带来 ≥1pp 的池质量提升则更有说服力；⑤ 效率/成本论证（判卷成本 vs 大模型方案）。

## 六、投稿前增补实验优先级

1. **BIRD dev 全管线一轮**（生成+分组+ORM+官方）——1-2 天，最高优先级。
2. **逐源消融**（1/2/3/4 源 × ORM/MI-VAV）——候选已在库，离线重算为主，1 天。
3. **RetrySQL 过门后的池融合**（在跑）——决定论文上限是否从 86.1 上移。
4. 判卷成本论证（CAPS 的 token 预算数据已有，反着用即可）。

## 七、结论

项目**已经具备 B 级会议的全部要素**：完整方法形态、可辩护的创新点（S1-S3）、严谨的验证协议、诚实的负结果。冲 A 的差距不在方法本身，而在**评测完备性（BIRD/消融/基线表）与最终数字**。若 RetrySQL 使池质量再上一个台阶（官方 >87），A 级概率显著上升。
