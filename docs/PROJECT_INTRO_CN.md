# 一、项目是什么

**一句话**：让"小学生"级别的 AI 模型（Qwen2.5-Coder-3B，3B 参数）在 Text-to-SQL 考试（把自然语言问题翻译成数据库查询语句 SQL）中考出接近甚至超过"研究生"（大模型/顶会论文）的成绩。

**学术定位**：小模型 Text-to-SQL 强化学习——"从复现到超越 FINER-SQL"（ICDE 2026 顶会论文，3B 模型 Spider 85%）。

**为什么值得做**：大模型做 SQL 题很强但贵、慢、难部署；3B 小模型若能接近同等水平，可低成本落地。

# 二、考卷与规则

- **Spider 数据集**：200 个真实数据库（演唱会/宠物店/体育联赛/民航等）+ 10,181 道"人话→SQL"题，由 11 名大学生人工编写。
- **三份卷**：train 8659 题（练习册，只做教学素材）；**dev 1034 题（公开考场，所有成绩在这里）**；test 2147 题（真高考试卷，答案保密，论文录用后官方服务器才准交一次）。
- **官方严格判卷**：每道 dev 题配有同一数据库的 25-60 个"变体版本"，答案必须在**全部版本**上都对才算分（防背答案）。这个机制是后来最大突破（MI-VAV）的钥匙。
- **三口径铁律**（PROJECT_GUIDE §6.5）：自定义执行匹配 / 原始 Spider（FINER 同源链）/ 官方 test-suite 三个口径不可混比；对外正式数字 = 全量 1034 + 官方 test-suite。

# 三、基础设施（怎么干活）

- **计算**：西交利物浦 HPC（slurm），A40×2 节点 + 3090 短作业分区；本地经女朋友电脑 cpolar 隧道跳板访问（端口漂移用公告板机制自动恢复，已实战三次）。
- **模型**：Qwen2.5-Coder-3B 基座 + LoRA；checkpoints 目录含三代蒸馏 SFT（sft_phase1/v2/v3）、GRPO 系列、orm_b1（判卷老师）。
- **引擎**：HF transformers（headline 贪心投票，保口径一致性）+ vLLM 0.11.2（采样类/大候选池，21× 加速；贪心字节一致不可达 → 双轨纪律）。
- **中央候选库**（candidate_store/）：所有生成的候选答案入库（模型/温度/种子/prompt 哈希索引），"生成一次，实验 N 次"。
- **裁决器体系**：src/adjudicate_pool.py（多实例执行分组投票）+ adjudicate_soft.py + adjudicate_order_aware.py，125+ 项单元断言。
- **自动化**：slurm 切片接力、后台守望进程、preflight 训练前检查（16 项）、实验记录器（records/experiments.jsonl）。

# 四、完整历程（十章）

## 第 1 章：起步（08-01~08-04）
3B 裸考 34% → 查出 6 个静默配置 bug（prompt 传字符串而非 chat 格式，模型 2 token 即停）→ 真实基线 45%。**教训：不报错的错最难找**（"优化器正常 ≠ 结果正确"范式 + grpo-preflight 检查）。

## 第 2 章：GRPO 实验矩阵（08-02~08-06）
- 奖励扫描：三级 1.0/0.1/0.0 是唯一有效配方（+5pp → 50% 天花板）；partial 奖励无效（组内扁平化→std→0→梯度归零）；数据量 100-7000 条无差别（瓶颈在梯度信号）。
- **投票发现**：多 prompt 投票 +21pp（50→71% 子集），5p 是甜点；投票抹平训练数据量差异。
- 7B 训练饱和（所有配方 ≤81% 基线）。

## 第 3 章：蒸馏教学（08-07~08-16）
大模型当老师出教案（DeepSeek API），三代剂量：v1(1176)→60.8%、v2(4428)→63.5%、v3(6444)→63.6%——**对数边际递减，加量饱和**。v4hard（难题讲解轨迹 5%）62.6% 回归，讲解式补课无效。

## 第 4 章：FINER 复刻与口径审计（08-06~08-12）
- 复刻 FINER-3B：自定义 vav ~85% 精确复现论文 85.88%（权重真实）；官方口径 76.6%。
- **P2 审计**：8.4pp 差距根因 = 评估器（test-suite vs 原始）+ 数据库（多实例 vs 单实例）双口径差，非模型问题。
- 解析器大修 557→0 解析失败（13+ 补丁）。

## 第 5 章：RL 训练侧封盘（08-13~08-14）
从强 SFT 起点三连败（T2.1 三级 49.4 / T2.2 四分量 50.2 / T2.3 Dr.GRPO 49.3，全部回吐 SFT 增益）。**决策：训练侧(RL)封盘**；三连负成为 L5 实证论文素材。

## 第 6 章：认知转变——选择缺口（08-14）
诊断：64 份草稿里 **95% 的题有正确答案，但投票只选对 67-71%**（maj@K 随 K 退化）。**差的 26 分不是不会做，是选错卷**。主战场从训练线转到选择线。

## 第 7 章：四次失败（08-14~08-15，全部是论文素材）
高温采样 ❌（66-68%）、few-shot 例题 ❌（68.9%）、质心过滤 ❌（自评 +0.5/官方 -1.1，口径错位第四证）、双模型十票 ❌（官方 68.3%，166 次平票）。离线分析发现：一致性坍缩（v2 比 v1 更一致且更易一起错）+ 跨模型 oracle 77.9%——**多样性必须来自独立来源**。

## 第 8 章：MI-VAV（08-15）★方法核心一
四组口径错位证据全部指向同一根因：**投票分组用单实例执行，官方评卷用多实例**。解法：分组判定搬到官方同款多实例执行（项目文档 E6 条目早有此想法）。
**成绩阶梯**：数票 66.8 → 单实例 vav 67.2 → 2 实例 71.5 → **全实例 74.3%（+7.1pp）**；跨模型池 +2pp。消融四维完整（池构成/实例数/过滤/裁决机制）。详见 MI_VAV_METHOD.md。

## 第 9 章：T1 免费改进四连（08-15~08-16）
修复链 NO-GO（胜者已全实例可执行）/ 难度门控 ✅（省 39.6% 预算零损失）/ 组级软排序 ⚪（持平，验证双模型组判别力 7.1×）/ 顺序敏感分组 ⚪（持平）。**结论：最大组规则已近似最优，免费午餐吃完。**

## 第 10 章：B2 三模型池（08-16，负）
三池 74.1% ≤ 两池 74.3%——同系第三模型无新信号（候选重复率 45%）。方法学发现：vLLM T=1.0 采样跨 run 不可复现 → 候选库 query-first 纪律。

## 第 11 章：ORM 判卷老师（08-16~08-19）★方法核心二
用 20,415 条自动打标数据训 3B Yes/No 判卷老师。**三级检验证据链（方法学亮点）**：
1. 同池考试 86.7% → 发现训练集污染（背答案）——检查链救场
2. 同门新题（v3 候选）官方 **82.4%**
3. 异门血统（p2a_500 候选）官方 **78.4%**（该池基线 67.7%，+10.7pp）——**铁证：学会的是判，不是背**

**最终方法（四源混合池 + ORM）**：四个不同血统的学生（v1/v2/v3 蒸馏三代 + p2a_500 GRPO 老模型）各交 16 份草稿（64 份/题）→ 多实例执行分组归阵营 → 判卷老师给阵营打分终裁。
- 生产口径（含同门新种子）：官方 **86.1%**（grouphead；argmax/hybrid 85.5）
- **论文头条（纯未见池 v3+p2a_500）：官方 83.4%**（argmax 82.9/hybrid 82.9）vs 同池 MI-VAV 74.27——+9.1pp 无懈可击

## 第 12 章：其余已关闭的方向（负结果清单，L5/L7 素材）
高温采样、few-shot 视角、质心过滤、修复链（执行失败触发）、组级软排序、顺序敏感分组、三模型同系池、难题讲解轨迹 SFT、逐字节 vLLM↔HF 贪心一致（bf16 数值物理不可达）——每个都有完整数据与归因。

# 八、关键教训（踩坑沉淀）

静默 bug 最危险；口径先行；评估器/数据库版本逐字节对齐；partial 奖励梯度归零陷阱；数据泄漏防不胜防（dev 轨迹、ORM 训练污染两连教训）；cpolar 端口漂移；调度器顺序异常（依赖作业用 --dependency）；vLLM 采样跨 run 不可复现；logprobs 上限 20（128 杀引擎）；gpua40n1 节点故障（换 n2）；"检查链"是项目最重要的隐形资产（6 静默 bug、口径审计、泄漏捕获、污染捕获全靠它）。

# 九、一句话总结

**我们证明了两件事：① 3B 小模型做 SQL 题，"会不会"已解决 95%，"选哪份答案"才是真战场；② 把官方判卷标准搬进"挑答案"环节（MI-VAV），再训练一个会看卷的老师（ORM），小模型从 41% 走到 83.4%——超过顶会论文同口径 6.8 分。每一次失败和被抓住的假象，都是论文里最诚实的素材。**
