## 阶段 0：起步与基线（08-01 ~ 08-04）

**思路**：复现 FINER-SQL（ICDE 2026，3B 模型 Spider 85%）之前，先摸清小模型 Text-to-SQL RL 的基线。

- 3B 裸考 45%（子集自定义）——期间发现并修复 **6 个静默配置 bug**（prompt 传字符串而非 chat 格式，模型 2 token 即停），基线从虚低的 34% 修正为 45%。教训沉淀为"优化器正常 ≠ 结果正确"范式 + grpo-preflight 检查。
- 证据：records/3b_baseline_v2.json、git log 08-01~08-04、PROJECT_GUIDE.md §10.1

## 阶段 1：GRPO 实验矩阵（08-02 ~ 08-06）

**思路**：扫描奖励设计（binary/三级/partial/atomic/finer）与数据量（100~7000）对 3B 的影响。

- **结果**：三级奖励 1.0/0.1/0.0 是唯一有效配方（+5pp → 50% 天花板）；partial 奖励无效（组内扁平化→std→0→梯度归零）；数据量 100-7000 条无差别（瓶颈在梯度信号）。
- **投票发现**：多 prompt 投票 +21pp（50→71% 子集），且 5p 是甜点；投票抹平训练数据量差异（单 prompt 43-50% → 投票全 70-71%）。
- **7B 结论**：所有训练配方 ≤ 81% 基线（7B 训练饱和，出路在投票与蒸馏）。
- 证据：records/experiments.jsonl 08-02~08-06、PROJECT_GUIDE.md §2.1

## 阶段 2：官方口径打通 + FINER 复刻（08-06 ~ 08-12）

**思路**：子集自定义口径不可信（前 100 条偏易 +10pp），必须全量 1034 + 官方 test-suite。

- 打通官方评估器（test-suite-sql-eval）+ 原始 Spider 评估器双链。
- **FINER-3B 复刻验证**：自定义 vav ~85% 精确复现论文 85.88%（权重真实）；官方口径 76.6%。
- **P2 口径审计（决定性）**：8.4pp 差距根因 = 评估器（test-suite vs 原始）+ 数据库（多实例 vs 单实例）双口径差，非模型问题。三路证据链：调用链/SHA256 逐字节核对/参数消融。
- **解析器大修**：557 → 0 解析失败（15 类模式、13+ 补丁）。
- 证据：PROJECT_GUIDE.md §8.2、docs/mac_sql_evaluator_diff.md、outputs/official_original_vav/

## 阶段 3：RL 训练侧封盘（08-13 ~ 08-14）

**思路**：蒸馏 SFT 把单次从 50% 抬到 60.8%（sft_phase1）后，尝试"从强 SFT 起点继续 RL"。

- **三连败**：T2.1 三级 49.4% / T2.2 四分量 50.2% / T2.3 Dr.GRPO 49.3%，全部回吐 SFT 增益（exec 88.8→82-84 同型退化）。
- **决策**：训练侧（RL）封盘——"RL 对 3B 从强 SFT 起点不 work"的三连证据成为 L5 实证论文素材。
- 证据：records/experiments.jsonl（grpo_t21/t22/t23）、PROJECT_GUIDE.md §2.4

## 阶段 4：蒸馏 SFT 剂量曲线（08-13 ~ 08-16）

**思路**：教学（蒸馏）是训练侧唯一有效路径，扫剂量。

- v1（1176 条）60.8% → v2（4428 条，3.8×）63.5%（+2.7pp）→ v3（6444 条，1.45×）63.6%（**+0.1pp，饱和**）。
- **结论**：剂量响应三点曲线（对数边际递减）——训练线"加量"已死，"提质"（FINER 配方/难题定向）才可能突破。
- 附：v4hard（340 条 train 难题讲解轨迹混入 5%）62.6% 回归——讲解式补课无效（格式分布不匹配），负结果入账。
- 证据：records/experiments.jsonl（sft_phase1/sft_v2/sft_v3/sft_v4hard）

## 阶段 5：选择线——诊断与四次失败（08-13 ~ 08-15）

**思路**（关键认知转变）：诊断发现 **Pass@K 95% vs maj@K 67-71%**——生成侧已解决，瓶颈在"从候选池中选出正确答案"（选择缺口 26pp@K64）。

四次失败（全部成为论文负结果素材）：
1. 高温采样投票（66.1-68.6%）——否证"多样性=提温度"
2. few-shot 例题 6 视角（68.9%）——视角变体无增益
3. 质心过滤（自评 +0.5pp / 官方 -1.1pp）——口径错位第四证
4. 双模型十票混合投票（官方 68.3%）——简单多数 166 次平票崩盘

**关键洞察（来自 0-A/0-B 离线分析）**：① v2 的 5 视角比 v1 更"一致"且一致还错得更多（一致性坍缩）——投票增益随基座质量递减；② 跨模型 oracle 上限 77.9%（自定义）——多样性必须来自独立来源。
- 证据：tmp_ab_analysis/RESULTS.md、records/experiments.jsonl 08-14~08-15

## 阶段 6：MI-VAV——多实例执行分组投票（08-15）★方法核心

**思路**：四组口径错位证据（MPEV 21pp、mixvav 自定义+/官方-、质心过滤 +0.5/-1.1、FINER 8.4pp）全部指向同一根因——**投票分组用单实例执行结果，而官方评卷用多实例**。解法：把分组判定搬到官方同款多实例执行上（项目文档 E6 条目早有此想法）。

- **B1 结果（决定性）**：实例数阶梯 多数 66.8 → 单实例 vav 67.2 → 2 实例 71.5 → **全实例 74.3%（+7.1pp）**；跨模型池 +2pp（72.2/71.8→74.3）。
- **消融完整**：池构成/实例数/过滤/裁决机制四维。
- 证据：docs/MI_VAV_METHOD.md、src/adjudicate_pool.py、outputs/adjudicate_b1/

## 阶段 7：T1 免费改进四连（08-15 ~ 08-16）

修复链 NO-GO（胜者已全实例可执行，触发率 0.77%）/ 难度门控 ✅（省 39.6% 预算零损失）/ 组级软排序 ⚪（持平，但验证双模型组判别力 7.1×）/ 顺序敏感分组 ⚪（持平，隐性彩票证实但净迁移为零）。

**结论**：最大组规则已近似最优，免费午餐吃完——剩余缺口必须靠训练型信号或更强池。
- 证据：records/experiments.jsonl（T1-3/4/5）、docs/SELECTION_V2_PLAN.md

## 阶段 8：B2 三模型池（08-16，负结果）

v1+v2+v3 三池 74.1% ≤ 两池 74.3%——同系第三 checkpoint 无新信号（候选重复率 45%），票数稀释。**结论**：多样性必须来自独立血统。附方法学发现：vLLM T=1.0 采样跨 run 不可完全复现 → 候选库 query-first 纪律。
- 证据：records/experiments.jsonl（B2_three_model_pool）

## 阶段 9：ORM 判卷老师（08-16 ~ 08-19）★第二方法核心

**思路**：文献（GradeSQL 等）指出训练型 outcome reward model 是唯一超过执行投票的方向；用自身 2 万候选+官方判定自动打标，训 3B Yes/No 判卷老师。

**三级检验证据链（方法学上最漂亮的部分）**：
1. 同池考试 86.7% → 发现训练集污染（判卷老师在背答案）——检查链救场
2. 同门新题（v3 候选）官方 **82.4%**（+8.1pp vs 项目最优）
3. 异门血统（p2a_500 候选）官方 **78.4%**（vs 该池基线 67.7%，+10.7pp）——**铁证：学会的是判，不是背**

**主战役（多源池）**：四源 64 候选 + ORM 组裁决 = 官方 **86.1%**（argmax 85.5 / hybrid 85.5；难度 easy 95.2/med 89.7/hard 82.8/extra 66.3）。诚实标注：含同门新种子红利；纯未见池干净头条实验在跑。
- 证据：src/train_orm.py、src/orm_selection.py、records/experiments.jsonl（ORM 系列）
