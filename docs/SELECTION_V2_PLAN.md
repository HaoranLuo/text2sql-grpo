# SELECTION_V2 — 投票选择器升级设计（2026-08-15）

> 基于 mix_vote（官方 68.3% 未赢）、maj_tgrid（选择缺口 ~26pp）、mem_filter（质心过滤 +4pp 子集）三大新数据的全面分析与下一阶段实验设计。

## 一、数据全景（截至 2026-08-15）

### 1.1 成绩账本（官方 EX 为主）

| 实验 | 自定义 | 官方 | 备注 |
|---|---|---|---|

| v2 单次 / 5p 投票 | 66.8% / 72.73% | 63.5% / 68.7% | 一致性坍缩（全票一致率↑、一致且错↑） |

### 1.2 三条机制结论（本设计的全部依据）

**结论 1：生成侧已基本解决。** Pass@K 曲线：K=8 时 84%，K=64 时 **94-95%**——64 个候选里 95% 的题已经"有正确答案"。继续优化单次生成（SFT v3 加料）是锦上添花，边际 ~+2pp。

**结论 2：选择侧是唯一大瓶颈，且现状是"越采样越差"。** maj@K 曲线 67-72% 不随 K 增长，K=32/64 时甚至**退化**（票数稀释）；maj10 十票 166 次平票；绝对多数命中率 94-98%（有绝对多数时基本可信）→ 选择缺口 = Pass@K − maj@K ≈ **13pp（K=8）到 26pp（K=64）**。这就是 L7《投票何时失效》的核心数据。

**结论 3：官方-自评错位是选择器的系统性缺陷，根源在"单实例执行分组"。** vav 按**单个数据库实例**的执行结果把 SQL 分组，被选中的"近似等价"SQL 在官方 test-suite 的**多实例**严格性下露馅。三证：MPEV 自评 85 vs 官方 64（21pp）；mixvav 自定义 +0.5pp vs 官方 −0.6pp；FINER 复刻 85 vs 76.6（8.4pp）。**修法不是调参，是把分组判定本身搬到多实例执行上（E6）。**

### 1.3 已排出的负方向（不再重试）

高温采样、few-shot 例题视角、单视角堆采样（maj@K 饱和且退化）、低一致题过滤门控（min-votes=3 锁错对象）、简单多数票（平票+错误多数派）、逐字节 HF↔vLLM 一致性（bf16 内核数值差，物理不可达）。

## 二、北极星与设计原则

- **北极星指标**：全量 1034 + 官方 test-suite EX。一切选择器实验以官方口径定生死；自定义/自评只做内部诊断。
- **双轨引擎**：headline 贪心投票用 HF（与 70.1% 基线逐字节可比）；采样类/大候选池/选择器实验用 vLLM（21×，96% 执行等价——对"统计选择"类实验足够）。
- **双线并行**：A40 链跑训练与基线评估（已满）；**选择器实验全部走 3090 vLLM 短切片 + CPU 执行**，不占 A40 队列。
- **候选库为底座**：所有 vLLM 生成入库（生成一次，实验 N 次）；选择器消融全部离线重算。
- **同 run 对照**：每个选择器实验必须与"同脚本同引擎的单模型臂"同 run 对比（mix_vote 的教训：跨 run 比数字会引入复制误差 1.2pp）。

## 三、实验设计

### 线 A：A40 主线（已在队列，不动）

E3×4（历史 checkpoint 全量 5p 投票，L7"投票抹平"闭合）→ sft_v3 训练（6444 条合并剂量）→ 5p×sft_v3 投票。预期 sft_v3 单次 ~65-66%、投票 ~72%+（官方），把整个"天花板"抬高一档。

### 线 B：选择器 v2（3090 轨道，本设计主体）

**B0 收尾现有数据（零 GPU，先做）**
- memf_full（1034 条切片接力中）→ 读全量结果；对过滤臂胜出答案跑官方复评（几分钟）→ 判断"质心过滤在官方口径是否幸存"
- maj_tgrid 两温度档 max-K 胜出答案 → 官方复评 → L7 曲线补官方口径点

**B1 旗舰：E6-B 大候选池 × 多实例 vav（核心实验）**

动机：结论 1（大池 Pass@K 95%）× 结论 2（选择缺口 26pp）× 结论 3（单实例分组是官方错位根源）→ 三者合一。

设计：
1. **生成**（vLLM，3090 单切片）：sft_phase1 + sft_v2 各 n=16 候选（T=1.0 采样，共 33088 次生成，~35 分钟），全部入库候选库（含 sft_v3 的后续补跑）
2. **裁决**（CPU 并行执行）：
   - 臂 1（基线）：单实例 vav（现行做法复现）
   - 臂 2（主治疗）：**多实例 vav**——候选在 test-suite 多实例库上逐实例执行，仅当两候选**在所有实例**结果一致才归同组；分组后最大组胜出（平票回退 v1 5p 胜者）
   - 臂 3（组合）：质心过滤 drop 20%（若 B0 证明其在官方幸存）→ 多实例 vav
3. **判定**：四臂同 run 对比 + 官方 test-suite EX 复评（北极星）

消融矩阵（全部离线，同一批候选重算）：

| 维度 | 取值 |
|---|---|
| 池构成 | v1 only / v2 only / v1+v2 |
| 池大小 n | 8 / 16 |
| 实例数 | 1（基线）/ 2 / 全部实例 |
| 过滤 | 无 / 质心 drop 0.2 |
| 裁决 | 多数票 / 单实例 vav / 多实例 vav |

主比较只报 2×2×3（池×实例×过滤）的子集；其余留作 L7 论文的机制曲线。

**B2 跨模型第三池（依赖 sft_v3 出数）**
- sft_v3 加入池：v1+v2+v3 × n=8（生成 ~30 分钟）→ 多实例 vav → 官方。三模型多样性 + 更高基线质量，是"选择器 v2 的完整形态"。

**B3（可选）L7 选择科学曲线**
- 全量 1034 的 maj@K × {单实例 vav, 多实例 vav} 曲线（K∈{8,16,32}）——"选择缺口随口径变化"是论文的机制图。

### 线 C：数据与论文（零 GPU，随行）

- 候选库持续灌数据；records/experiments.jsonl 每实验闭环
- L7 素材清单更新：选择缺口曲线、口径错位三证、maj@K 退化、质心过滤官方幸存与否

## 四、Gate 与决策点

| Gate | 条件 | 通过 → | 不过 → |
|---|---|---|---|
| G-B0 | memf_full 官方复评：过滤臂 ≥ 基线臂 | 质心过滤进入 B1 臂 3 | 过滤只作为 L7 数据点，B1 只跑臂 1/2 |
| **G-B1（主 Gate）** | 多实例 vav 官方 ≥ 同 run 单实例 vav + **2pp** | 选择器 v2 成立 → L4 方法核心组件；接 B2 | 官方错位另有根源（深挖：多实例下"全对"组稀薄？）→ 转 L7 纯机制叙事 |
| G-B2 | 三模型池 ≥ 二模型池 + 1pp | 论文方法定稿（多池+多实例裁决） | 二模型池定稿 |

**G-B0 已判定（2026-08-15）：FAIL。** 全量 1034 官方复评：基线 maj@16 vav = 70.0%，drop 0.2 过滤臂 = 68.9%（-1.1pp），而自评口径过滤臂是 +0.5pp（81.53→82.01）。**自评有效、官方反向**——口径错位第四证。决策：质心过滤退出 B1 臂 3，降级为 L7 数据点。

**G-B1 已判定（2026-08-15）：PASS，决定性胜利。** 全量 1034 官方 EX：

| 臂（both 池） | 官方 EX |
|---|---|
| 文本多数票 | 66.8% |
| 单实例 vav（旧做法） | 67.2% |
| 2 实例 vav | 71.5% |
| **全实例 vav（主治疗）** | **74.3%** ← 新项目最优 |

- 治疗效应 **+7.1pp**（远超 +2pp 门槛）；跨模型池 +2.0pp（v1_only 72.2 / v2_only 71.8 / both 74.3）
- 超过历史最优 v1-5p 70.1%（+4.2pp）；距 FINER 官方 76.6% 仅 2.3pp（且无大规模 GRPO）
- 官方-vs-自评错位根因实证 = 单实例执行分组；多实例分组根治。**L4 方法核心组件定稿：Multi-Instance Execution-Group Voting (MI-VAV)**
- 成本：33088 次生成（vLLM ~90 分钟）+ 760K 次执行（CPU 14 分钟）

**附：maj_tgrid 官方口径点（100 条，max-K=64 胜者）**：T=0.7 → 70.0%；T=1.0 → 68.0%。温度在官方口径同样无增益（甚至略负）。

## 六、风险清单

1. **多实例执行成本**：test-suite 每题库有多个实例（最多 20+），32 候选 × 全实例的执行量可能爆（对策：先 2 实例起步，消融实例数；执行缓存 + 16 线程；超时剪枝）
2. **多实例下"全对组"稀薄**：严格等价下组碎片化，最大组可能不存在——平票规则（回退 v1 5p 胜者）被高频触发则治疗无效（监控触发率，报告里必须报）
3. **复制误差教训**：B1 的"单实例 vav"基线臂必须用与历史同源脚本生成（复用 mix 的投票代码路径），否则同 run 对比失真
4. **vLLM 采样与 HF 历史曲线不可混比**：B1 是"池内相对比较"，绝不与 HF 生成的历史绝对数直接相减
5. **3090 槽位冲突**：memf 切片与 B1 共享 3090，按"谁更短谁先跑"排队
