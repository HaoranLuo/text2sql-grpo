## 一、TOP 发现(6 条)

1. **QAE 修复梯度退化**:GRPO 组均值 baseline 是熵塌缩/爆炸的根源;换成组内 K-分位数(K≈0.4),二元执行奖励下退化为一行 if-else 的"难题只强化罕见成功、易题只惩罚残余失败"两阶段门控——是唯一被理论和实验同时支撑的零成本优势估计修复。**3B 比论文的 8B 更易熵塌缩,熵塌缩直接压扁投票候选分布**——它是连接训练端与"投票何时失效"机制论文的直接因果链。
2. **投票收益 = 候选质量 × 候选多样性**:四篇论文各自量出了乘积的一条边——GRPO 后 Pass@K 略降但 Average@K 显著升(Reasoning-SQL A.4,多样性下降);maj@ 在 32 附近饱和且更大无益(PaVeRL);温度 1.0 与 30 候选饱和(FINER-SQL);执行分组数 + Self-BLEU 可直接量化票数稀释(FINER Table IV)。"投票何时失效"机制论文的骨架可直接建在这张表上。
3. **稠密部分正确奖励是 3B 纯 GRPO 不崩溃的必要条件**:FINER-SQL atomic+memory 合计 +4.4 EX(3B 消融);0.5B 去掉 memory 后语法错误率 19.6%→31.5%;PaVeRL 的非负列级奖励(10×EX_f)进一步证明连续奖励显著提升稳定性与样本效率。两条硬约束:**只用非负奖励**、**混合正负奖励会破坏 GRPO 稳定性**——任何新奖励组件加入前必须满足。
4. **奖励堆叠存在一条可机检的黄金不变量**:错误 SQL 的总奖励永远不可能超过正确 SQL(Reasoning-SQL:exec 权重 3 主导、judge 2、其余各 1);同时 PaVeRL 警示列级奖励可被 SELECT * 投机拿满分。这两条原则同时防奖励黑客与梯度信号倒挂,**可写成 grpo-preflight 的自动化检查项**。
5. **memory reward 是文献中唯一在训练端直接优化投票一致性的组件**:3B 执行分组 6.21→5.27、Self-BLEU 0.674→0.724;其"跨库推理质心检索"可以零训练成本搬到推理端当候选过滤器。项目已复刻 FINER 85%(atomic+memory 大概率已在管线中),把 Table IV 指标纳入评估协议后,该组件就是 MPEV 投票升级与机制论文的第一个受控实验点。
6. **GRPO 模型涌现的推理轨迹本身就是最好的 few-shot 提示**(Reasoning-SQL Table 4:涌现风格 > Divide-and-Conquer/Query-Plan/ACT-SQL 等人手策略,且跨模型可迁移);同时**纯 SFT 在 OOD 基准(Spider 系)上会退化到基座以下**(7B 77.85→68.08,GRPO 恢复到 78.72)。前者给 Phase 3 投票一个零训练成本的候选多样性来源;后者直接威胁 Phase 1 管线设计——若蒸馏 SFT 已 OOD 退化,论文证明可以跳过 SFT 直接基座+GRPO。

## 二、可落地实验清单(9 条,按计划阶段归档)

### Phase 1-SFT
| 实验 | 预期收益 | 成本 |
|---|---|---|
| **OOD 退化监控与"跳 SFT"决策**:建立 Spider-Syn/Spider-DK 类 OOD 验证集,SFT 后、GRPO 前各测一次;若 SFT 已退化到基座以下,按 Reasoning-SQL 结论直接基座+GRPO 或大幅缩短 SFT;顺带人工审计空结果样本(WHERE 1=0 类,约 7%) | 规避 SFT 记忆化导致的 OOD 塌方 | 评估脚本 + 推理,约 0.5 GPU 天 |

### Phase 2-GRPO
| 实验 | 预期收益 | 成本 |
|---|---|---|
| **QAE 分位数 baseline A/B**:现有 GRPO 脚本的优势计算处把组均值 baseline 换成 K-分位数(K∈{0.3,0.4,0.5}),其余超参不动,训练中记录熵、正优势占比与执行分组数 | pass@1 相对 +5~20%;核心收益是熵稳定 → 投票候选多样性受保护 | 零 API;3 次小规模 3B 训练约 1-2 GPU 天;改一个优势估计函数 |
| **奖励栈 v2**:FINER 四项之上增加非负列级奖励 R=10×EX_f(执行成功=列匹配比例、执行错=0.5、失败=0),训练前预执行金标 SQL 缓存结果表;同时加输出列数惩罚/EX_b(τ=5)门禁防 SELECT * 投机;用"错误 SQL 总奖励 < 正确 SQL"不变量做自动化回归校验 | 训练稳定性与样本效率双升,预期 dev EX +1~3pt | 一个 reward 函数文件 + 一次性金标预执行(CPU 级);2 次消融训练约 2-4 GPU 天 |
| **熵崩溃监控 + 难度分桶**:GRPO 日志按查询难度(组内执行成功率)分桶记录熵、正优势占比、pass@1;离线统计 p≤1-K 的组占比验证两阶段门控假说;把熵/优势分布/奖励不变量三项加入 grpo-preflight 检查清单 | 提前发现 3B 熵塌缩(预期比 8B 更早),为 K 选值提供依据 | 日志与统计脚本约 0.5 人天,零 GPU |
| **两阶段 GRPO 调度(PaVeRL 重启)**:阶段 1 约 10 epoch(3% 平坦 warmup→线性升到 max LR→余弦衰减);阶段 2 从阶段 1 greedy EX 最佳 checkpoint 重启(平台期→max LR 重启、无趋势波动→LR 减半),再 10 epoch 余弦衰减 | 样本效率提升,10 epoch 内收敛;同等算力 +0.5~1.5pt | 每 1-2 epoch 存 checkpoint + dev greedy 评估(已有脚本) |

### Phase 3-投票(全部零训练或纯推理)
| 实验 | 预期收益 | 成本 |
|---|---|---|
| **投票失败诊断曲线(机制论文 Figure 1 素材)**:当前最佳 checkpoint 在 BIRD/Spider dev 上测 maj@{8,16,32,64} × 温度{0.7,1.0} 网格,同时记录 Pass@K vs Average@K、Self-BLEU、执行分组数、绝对多数命中率 | 定位本项目投票饱和点(文献:32 附近最优、30 后饱和、temp 1.0 最优),预期投票端 +1~3pt 超参收益;"投票何时失效"的核心数据 | 纯推理零训练,约 0.5-1 GPU 天 |
| **Memory 质心推理端过滤消融**:先复现 FINER Table IV 评估(执行分组数、Self-BLEU),再用已训练的 memory 模块对 30 候选做跨库质心相似度过滤,剔除相似度最低的 20~30% 候选后再多数投票,与无过滤基线对照 | 若分组数下降则票数更集中、MPEV 票数稀释缓解,预期 +1~2pt;即使无增益也产出机制论文"一致性干预"受控数据点 | 纯推理 + CPU 级嵌入前后端,约 0.5 GPU 天,零训练;推理端消融先于任何训练改动 |
| **涌现轨迹 few-shot 投票变体**:收集本项目 GRPO 模型对高难度样本的 3 条成功推理轨迹,按 Reasoning-SQL Table 4 做成 few-shot prompt 变体,与现有 prompt 并行采样后合并投票 | 纯 +1~2pt(论文跨模型 50.19 vs 48.82 量级);主要贡献是候选多样性 | 一次轨迹收集 + 推理评估,约 0.5 GPU 天 |

### 暂缓(成本/风险高,备查)
- **judge 奖励(RLAIF)**:仅对 exec=0 的 rollout 调用强模型按 12 条 rubric 打分(0-2,权重 2);文献量级约 +1pt;API 预算敏感,且论文内部打分范围不一致需自行定标
- **Verbal RL 蒸馏增强**:每问采样至 10 个可执行候选 + 每候选 20 次自打分选最优做 SFT 数据;打包收益 +4pt(Spider2.0)但 API 成本极高,3B 自评质量不足可能倒贴

## 三、优先级建议(合成结论)

**先做零训练成本的诊断与投票实验**(投票失败曲线 → memory 质心过滤 → few-shot 轨迹变体):项目已复刻 FINER 85%,这些实验直接产出机制论文数据和投票端收益,且不与训练主线抢 GPU(推理插队 gpudebug)。**随后**在 Phase 2 加入 QAE baseline 与奖励栈 v2 消融(文献验证过的最高性价比训练改动)。**Phase 1 增加 OOD 监控**作为"跳 SFT"的决策依据。
